# ADR-0002: 壓縮檔是唯一真相,散檔一律衍生;內容以 SHA-256 定址去重

## 狀態(Status)

Accepted。已對真實素材庫執行(2026-08-09,5,456 → 59 個檔案),見 `docs/architecture.md` 階段 3。

## 背景(Context)

初始設計假設散檔是真相來源,這個假設在確認「未來素材都以壓縮檔匯入」後不成立。
掃描既有素材庫發現散檔與壓縮檔同時存在,同一份資料存兩遍,且雲端備份要同步 5,721 個
小檔(絕大多數是幾百 bytes 的小圖示)。

## 決策(Decision)

- **`library/**/*.{zip,rar,7z}` 是唯一真相**,不可變,是備份目標。索引一個壓縮檔內的資源
  不需要解壓:項目路徑/大小/CRC32 從 central directory 直接讀;SHA-256、圖片尺寸只需串流
  解壓該筆項目,不落地;縮圖才需要完整解碼一次,結果進可重建的快取。
- **內容以 SHA-256 定址去重**(`blobs` 表,`sha256` 為 PRIMARY KEY)。多家廠商常附上同一份
  免費字型或授權文字,同一內容只算一次縮圖、只存一份快取。
- **`library/studio/`(自製素材)是唯一例外**,維持散檔 + git —— 這類素材會被頻繁編輯,
  壓縮檔會變成阻力。這是有理由的例外,不是設計不一致。
- **重構(散檔→壓縮檔遷移)的安全閘門**:掃描 → dry-run 計畫 → 執行(寫入 `moves` 表)→
  對帳(搬移前存在的每個雜湊,搬移後必須仍然存在)→ **只刪除經逐筆雜湊證明確實存在於
  某個保留壓縮檔內的散檔**,任何對不上的檔案一律保留並列入報告 → undo manifest。

## 考慮過的替代方案(Alternatives Considered)

- **維持散檔為真相**:被使用者明確否決(未來素材都以壓縮檔匯入)。
- **重新打包廠商壓縮檔(統一格式)**:明確不做 —— 位元級原檔是授權與版本比對的依據,
  重新打包會破壞這個保證。
- **用檔名+大小做去重代理指標**:曾用於前置盤點(`docs/_archive/PACKS.md` 的覆蓋率驗證),
  但明確標註「這是前置檢查,不是刪除依據」,正式判定一律用 SHA-256。已有一次代理指標
  誤判紀錄(BDragon1727 的 Free 壓縮檔,誤以為是 Full 版子集,SHA-256 掃描證明並非如此)。

## 影響(Consequences)

- 誠實的但書:PNG 本身已壓縮,zip 幾乎省不到體積;真正收益是備份檔案數從 5,721→59、
  重複儲存消失、廠商原檔位元級完整可供授權爭議查證。實測磁碟只省 131.9 MiB(先前估的
  1.4 GB 是錯的)。
- 建專案時「只對選中項目做單筆解壓」,永遠不整包解開,搭配 `prefersBulkExtraction` 對
  solid 壓縮格式(rar/7z)做例外處理以避免 O(n²) 成本(見 ADR-0005)。
- `blobs` 去重層意味著同一內容若被多個 `assets` 列引用,刪除其中一個 asset 記錄不可
  連帶刪除 blob,需要額外的引用計數或悲觀保留策略(目前程式碼未見主動垃圾回收,
  縮圖快取可隨時整批刪除重建,風險可控)。
